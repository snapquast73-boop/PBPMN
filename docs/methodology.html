Data & methodology

This site is a viewer. It holds no baseball data of its own. Each page load asks MLB's Stats API for one date's schedule and, when you open a game, for that game's official feed. The response is rendered as received.

1. The only source

PurposeRequestDocumented by
Schedule for one date GET https://statsapi.mlb.com/api/v1/schedule?sportId=1&startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&gameTypes=R,F,D,L,W&hydrate=linescore Response observed live; see Flagged for Review row V2
One game, complete GET https://statsapi.mlb.com/api/v1.1/game/{gamePk}/feed/live Response observed live; row V4
Sport identity check GET https://statsapi.mlb.com/api/v1/sports/1 Row V1 — returns "Major League Baseball", id 1

2. Scope

  • sportId=1 (Major League Baseball).
  • Game types R (regular season), F (wild card), D (division series), L (league championship series) and W (World Series).
  • Dates from 2014-01-01 forward. Dates before Opening Day legitimately contain no qualifying game, and the page says so rather than substituting anything.
  • Spring Training, exhibition games and the All-Star Game are outside the requested scope.

3. Acceptance rules

A response is used only if all four checks pass:

  1. the URL is HTTPS on the exact host statsapi.mlb.com (checked before the request is made);
  2. the HTTP status is successful and the body parses as JSON;
  3. the body carries MLB Advanced Media's notice — the string MLB Advanced Media, L.P. must appear in copyright;
  4. a game feed's gamePk — and, when present, gameData.game.pk — equals the requested gamePk.

A failed check produces an explicit error in the status line. The page never falls back to a cached copy, a sample game or a computed substitute.

4. What is displayed

Line score liveData.linescore.innings[].{num,away{runs,hits,errors,leftOnBase},home{…}}, liveData.linescore.teams.{away,home}.{runs,hits,errors,leftOnBase}, liveData.linescore.note, currentInning, inningState
Play-by-play liveData.plays.allPlays[].about.{inning,halfInning,atBatIndex,isScoringPlay,isComplete}, result.{event,description,awayScore,homeScore}, count.{balls,strikes,outs}, matchup.{batter,pitcher}.fullName, playEvents[].details{pitchData,hitData}, runners[].{movement,details}

Average column

In-game batting splits returned by MLB do not include a batting average, on-base or slugging figure; only the season split (seasonStats.batting.avg) does. The AVG column therefore shows the season average supplied by MLB and nothing else. It is never computed on this page.

5. Event log

While a game is Live the page re-requests the official feed at the interval MLB supplies. Each poll is reduced to a snapshot and compared with the previous one. Recorded changes:

  • game-state — status.detailedState changed;
  • score — a side's runs in liveData.linescore.teams changed;
  • scoring-pending — a play appears with about.isComplete = false (the official ruling is not final);
  • ruling-resolved — that play later reports about.isComplete = true;
  • ruling-change — an existing play's result.event, result.eventType or result.description changed between polls;
  • review-open / review-decided — about.hasReview with reviewDetails.inProgress, and the reviewDetails verdict (isOverturned, reviewType) copied verbatim.

The log is stored in this browser under mlb-pbp:eventlog:v1:<gamePk>. It is never sent to a server and never written into the repository. It is a record of what the page watched, not an official document.

6. Downloads

FileContents
<gamePk>.txt Readable report: provenance, game header, line score, decisions, play-by-play with every pitch/action and runner movement, box score.
<gamePk>.json The exact response text, byte for byte, with its SHA-256 shown in the report.
<gamePk>.events.ndjson One JSON record per line: metadata, then one play per at-bat, then one event per pitch or action.

7. Limitations

  • If MLB changes a completed game after you downloaded it, your copy is the older official response. Re-open the game to fetch the current one.
  • The page depends on MLB continuing to serve these endpoints with a permissive CORS header; both were verified (see Flagged for Review, row V19) and both are outside this project's control.
  • Times are shown in your browser's local time zone, labelled with that zone; the official UTC timestamp is in the downloaded report.
  • No value is ever inferred. Where MLB omits a field, the interface states the omission instead of guessing.
